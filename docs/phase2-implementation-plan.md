Migration files are generated by Django; the empty Django-generated guard migration is filled with reversible RunSQL. No existing migration is rewritten after development application.

## Automated verification

Schema tests cover valid/invalid relationships, missing/duplicate serials, immutable unique tags, modes, quantities/units, hierarchy validation, specification XOR/type validation, open custody uniqueness, return history, audit evidence/uniques, staging/source uniqueness, protected deletion, PostgreSQL indexes/trigger catalog and timezone-aware timestamps.

PostgreSQL TransactionTestCase tests use two independent connections for competing assignments and verify rollback of a multi-write transaction on constraint failure. This validates schema behavior, not a nonexistent posting service. Fixtures modify only the isolated test database; no live stock is seeded. Full test counts/results are in the validation report.

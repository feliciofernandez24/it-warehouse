# Phase 3B.2B.2 registration transaction

Status: proposed algorithm, not executable implementation. Depends on [gateway prerequisites](phase3b2b2-write-gateway-design.md). The current B.1 read-only inspect_request does not implement capture replay: capture has no supplied revision ID, while stored events reference an allocated revision. Use a dedicated receipt path, not the existing revision comparison.

## Before SQL

Authenticate session, verify CSRF, reject identity fields in the client body and generate/validate a request UUID. Stream into private quarantine with compressed/expanded resource limits. The verifier reads the exact staged bytes once with pinned production profile/configuration, derives manifest and normalization preview, and independently reconciles all rows/classes/layout/counts. Publish original workbook and capture artifact durably and obtain a retention reservation. Obtain identity and verifier assertions bound to the complete request. No database locks during parsing, signing or storage I/O.

Fingerprint = SHA256(canonical({domain: "itw.capture-request.v1", actor_id, action: "register_verified_capture", request_id, revision_id: null, expected_version: null, envelope_digest})). Canonical UUIDs use lowercase hyphenated form and digests lowercase hex. Envelope digest hashes the exact canonical envelope; neither mutable filenames nor assertion expiry/signature bytes belong in the fingerprint. Renewed assertions can therefore authorize the same retry.

## One atomic registration

Use a dedicated connection/transaction, READ COMMITTED, not a caller's unrelated or pre-locked transaction. Bound argument sizes before parsing; verify cryptographic assertions and request/envelope/capture relationships, then:

1. Acquire pg_advisory_xact_lock(73921,2) before any database row lock, INSERT or sequence-driven business mutation. Recheck expiry/key status, current active actor and exact capture permission using fresh post-lock statements. A preflight result is never authority.
2. Read receipt by globally unique request UUID. If it exists, require actor, fingerprint and envelope match and current authorization. Return the immutable original result after signature checks; do not create an event, participant or revision and do not return current revision state as the original result. Different actor/content/action returns REQUEST_CONFLICT without evidence disclosure.
3. For a new request, check consumed nonce/assertion records, verified immutable profile/policy, source claim and legacy ImportBatch hash matches. If the workbook already belongs to a different request, fail DUPLICATE_SOURCE even if content matches. No legacy adoption and no automatic profile substitution. A UUID already used by an unrelated review event is REQUEST_CONFLICT.
4. Independently verify capture bytes SHA-256, canonical encoding, nested manifest/layout and internal preview digest semantics, workbook/profile binding, row hashes, full row set, coordinate uniqueness and all class/count reconciliation. Verify the independently signed envelope and exact immutable storage versions/receipt. SQL does not claim to reparse the original OOXML: workbook-to-manifest authenticity depends on the isolated trusted verifier.
5. Insert source claim and ImportBatch: server-generated public UUID, safe fixed original_filename such as verified-source.xlsx, file_sha256 from envelope, source_storage_key for original workbook, uploaded_by from verified actor, server timestamps, mapping_version from pinned normalization version, Asia/Tokyo, status UPLOADED, no reviewer/timestamps/approval digest and empty notes. No caller-set SQL IDs, time or status.
6. Insert ALL populated ImportStagingRecord rows in sheet-ordinal/row order, including HEADER and SEQUENCE_ONLY. raw_values is the exact raw_cells array. normalized_values is only {capture: {domain, workbook_sha256, section_header, classification}} using source-row domain itw.source-row.v1; together with sheet/row/raw_values it reconstructs the hash payload. source_row_digest is recomputed. status CAPTURED, validation arrays empty, asset/stock_balance/promoted_at null. Do not write preparation decisions into these immutable source rows.
7. Insert revision UUID: revision_number=1, parent=null, state CAPTURED, version=1, created_by=uploader, verified source_profile, layout/manifest digests, capture_storage_key for preview artifact and capture_artifact_digest, draft_payload={}. Source rows precede revision because 0003 freezes subsequent source inserts. Revision insertion checks owner/profile/counts.
8. Insert uploader participant explicitly; then insert sequence-1 CAPTURE event from CAPTURED to CAPTURED, actor=uploader, request UUID/fingerprint, no snapshot/source_row/review_event/signature fields, fixed reason_code VERIFIED_SOURCE_CAPTURE and fixed nonblank reason. Existing event trigger inserts participant ON CONFLICT DO NOTHING, so the explicit insert yields exactly one participant. details contains envelope/receipt digests and after_payload_digest computed by PostgreSQL as encode(sha256(convert_to(draft_payload::text,'UTF8')),'hex'). This existing JSONB-text digest is distinct from Python canonical hashing.
9. Insert immutable receipt, claim links and nonce-consumption records in the same transaction. Result bytes use domain itw.capture-result.v1, request UUID, batch public UUID, revision UUID, event ID, original state CAPTURED and version 1 plus envelope digest. Store exact canonical result and its digest, not merely a lookup into mutable revision state. Deferred guards require one matching receipt/claim/event/participant and no snapshot for every new capture.
10. Force deferred constraints IMMEDIATE before function return; retain normal outer commit checking. Function return is provisional until COMMIT succeeds. Publish HTTP success only after commit, outside the atomic block. No broker/storage callback while holding the lock.

Any validation, insert, trigger, deferred-constraint or commit error rolls back ALL database changes, including nonce consumption. Sequence gaps after rollback are expected, never identity evidence. Never swallow errors to continue in an aborted transaction. Map fixed sanitized codes outside the failed transaction.

## Locks, retries and conflicts

Global order is advisory (73921,2), then auth/policy/key reads, receipt/source claim, existing batches ascending PK, revisions ascending UUID if needed. Capture creates only one new batch/revision and never locks stock rows. Future multi-object operations must retain Phase 2C ordering: assets ascending PK, products/buckets, reversals/custody; capture must never call posting or take those locks first. Advisory serialization intentionally limits throughput and coordinates stock/audit/hierarchy work; do not replace it with a capture-only lock.

Unique request/nonce/source constraints remain final defenses if a path accidentally omits the lock. Same request races serialize; one commit, one exact replay. Different requests for identical workbook serialize; one commit, one DUPLICATE_SOURCE. Same request/different envelope is always conflict. Same artifact by a different uploader cannot disclose or reuse the original receipt. Key/permission revocation races follow the gateway coordination protocol.

Only lock timeout, deadlock, serialization failure or uncertain connection/commit outcome permit a bounded retry with SAME request UUID/fingerprint. Reauthenticate and renew expired assertions without changing the envelope. Used nonce is acceptable only for its exact committed receipt; otherwise replay is denied. An expired assertion alone never authorizes a historical response. Current revocation may deny replay without undoing the earlier commit.

After an unknown commit outcome, query through the same authenticated register/replay path. Never infer rollback from a network error, mint a new UUID or delete artifacts. Retry conflicts, authorization failures and integrity errors require operator/user correction, not automatic retry. No failure batch or partial revision is persisted; sanitized security telemetry is separate from capture evidence.

## Artifact failure windows

Crash before publication: quarantine cleanup. Publication before SQL commit: protected orphan eligible only for coordinated delayed collection. SQL commit before response or receipt pin acknowledgment: durable database reference wins over lease expiration; collector rechecks SQL references before deletion. Missing storage after commit: integrity incident and exact-version restoration, never another capture batch. Storage reservation validation must ensure collection cannot race the transaction's commit; without that protocol implementation must stay disabled.
